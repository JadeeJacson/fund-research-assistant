# v1 实施路线图

## 总体规则

- 每个里程碑使用独立小 PR；
- 先定义契约和测试，再扩展实现；
- 未达到验收条件的能力不写入 README“已实现”；
- 不用大规模重写掩盖当前可运行原型；
- 每次数据库变化都包含 Alembic 迁移和回滚说明。

## M0：计划与规范

交付：

- 产品范围和成功标准；
- 当前状态与迁移边界；
- 架构、数据来源、OCR、决策引擎；
- 前端交互、测试、安全和 AI 规范；
- 后续里程碑。

验收：

- 文档之间参数一致；
- 清楚区分当前 v0.1 与目标 v1；
- 所有已确认用户决定均有归属；
- 不承诺尚未实现的功能。

## M1：前后端骨架与迁移底座

交付：

- `frontend/` React + TypeScript + Vite；
- `backend/` FastAPI、领域层和应用层；
- SQLite、SQLAlchemy、Alembic；
- `/api/v1/health` 和统一错误结构；
- 单命令本地开发入口；
- CI：lint、typecheck、unit test、API test、最小 Playwright。

验收：

- Windows 和 CI 能从空数据库启动；
- 健康页展示数据库、OCR、Provider、AI 状态；
- 示例按钮具有真实 API 往返和成功/失败反馈；
- 不破坏 `main` 的 v0.1 启动方式，直到替代流程验收。

## M2：候选基金与购买前研究

交付：

- 手工输入六位代码；
- 基金身份、份额和类型校验；
- 候选列表、详情和 2～3 月/约 1 年期限；
- AKShare Provider、缓存和官方事实核对接口；
- 指数、主动权益、普通债券的基础指标；
- 数据不足和未支持类型门控；
- 确定性研究报告，不依赖 AI 也可运行。

验收：

- 固定样例可复算；
- A/C 份额不混淆；
- 每个数字有截止日期和来源；
- Provider 失败时显示缓存或明确降级；
- 候选添加、刷新、研究、比较全程无空按钮。

## M3：截图 OCR 与导入中心

交付：

- 候选、持仓、交易截图上传；
- RapidOCR 本地流水线；
- 页面分类、版面组合和基金身份匹配；
- 草稿校对、部分确认、去重和冲突处理；
- 导入批次历史和原图保留设置。

验收：

- 上传样例和脱敏回归集通过；
- 多图重叠不产生重复正式交易；
- 截断名称和低置信度必须人工确认；
- 未确认草稿不参与计算；
- 正式数据误写入率为零。

## M4：持仓、组合与建议

交付：

- 持仓快照和交易账本；
- 暴露、重叠、相关性和集中度；
- 组合收益和现金流口径；
- 目标区间、市场状态调整和压力测试；
- 建仓、加仓、持有、暂停、减仓、退出复核；
- 数值触发器、有效期和手动检查。

验收：

- 两套期限分别输出；
- 10% 回撤只作为风险参考并显示局限；
- 行业比例由规则约束并可回放；
- 所有操作状态能追溯到输入和规则；
- 缺交易详情时不伪造精确成本或收益。

## M5：证据管线与 DeepSeek

交付：

- 官方披露和可靠事件证据；
- Evidence Pack、去重、截止日期和可信等级；
- DeepSeek 文本 Provider 与 Mock Provider；
- 结构化解释、反方观点、引用和未知项；
- AI 失败降级。

验收：

- 图片和完整个人流水不发送给模型；
- 每个事件引用有效 `evidence_id`；
- 模型不能改变核心数字和操作状态；
- 旧模型名不写死；
- 无 AI 密钥时主要功能仍可用。

## M6：触发监测、打包与部署准备

交付：

- 本地手动刷新和可选 Windows 定时任务；
- 备份、恢复、导出和诊断；
- Windows 本地打包；
- 性能、可访问性和安全基线；
- C 端部署差距清单。

验收：

- 定时检查失败不丢任务；
- 可从备份恢复到一致状态；
- 新机器按文档完成安装；
- 全量端到端流程通过；
- 未完成认证、租户隔离和合规前不公开部署。

## PR 顺序建议

1. M0 文档；
2. M1 仓库布局、后端骨架和迁移；
3. M1 前端骨架与真实交互；
4. M2 基金身份与 Provider；
5. M2 指标与候选研究；
6. M3 OCR 基础和样例回归；
7. M3 校对与正式导入；
8. M4 组合计算；
9. M4 决策与触发器；
10. M5 证据和 AI；
11. M6 打包、监测和部署准备。

每个 PR 都应能独立测试和回滚。若实施发现规范不可行，先在同一 PR 更新对应文档并说明原因。
