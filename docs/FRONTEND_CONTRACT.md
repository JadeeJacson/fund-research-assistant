# 前端交互与 API 契约

## 1. 原则

前端必须真实反映业务能力。任何可点击按钮、菜单、卡片或开关都必须有明确动作、后端契约和结果反馈。尚未实现的功能不展示为可操作控件；可以显示带说明的只读路线图，但不能放置空按钮。

每个异步动作都处理：

- `idle`
- `loading`
- `success`
- `empty`
- `validation_error`
- `server_error`
- `offline`
- `disabled`
- `retry`

写操作成功后必须更新页面状态并持久化；刷新页面后结果仍存在。

## 2. 页面地图

| 页面 | 核心任务 |
| --- | --- |
| 总览 | 数据新鲜度、实验组合、待复核事项、触发状态 |
| 候选基金 | 手工添加、截图导入、比较、发起研究 |
| 基金研究 | 查看事实、指标、证据、结论和触发器 |
| 持仓 | 查看快照、暴露、重叠、目标区间和操作状态 |
| 交易 | 导入、校对、确认和查询流水 |
| 导入中心 | 管理批次、OCR 草稿、冲突和错误 |
| 数据与任务 | 刷新 Provider、查看缓存和任务状态 |
| 设置 | 风险参数、AI、数据源、隐私和备份 |

移动端保持可读，但 v1 验收以桌面浏览器为主。

## 3. 核心控件契约

| 控件 | 用户动作 | API/业务结果 | 必须反馈 |
| --- | --- | --- | --- |
| 添加候选 | 输入代码并确认 | `POST /api/v1/candidates` | 身份校验、重复提示、成功新增 |
| 上传截图 | 选择/拖入图片 | `POST /api/v1/imports` | 文件校验、上传进度、批次 ID |
| 开始识别 | 启动 OCR | `POST /api/v1/imports/{id}/process` | 任务进度、失败重试 |
| 确认导入 | 提交校对字段 | `POST /api/v1/imports/{id}/confirm` | 写入数量、冲突、持久化 |
| 刷新公开数据 | 拉取 Provider | `POST /api/v1/funds/{code}/refresh` | 数据截止日、来源、错误 |
| 生成研究 | 选择期限并运行 | `POST /api/v1/reports` | 任务状态、报告版本 |
| 比较候选 | 选择 2～5 只 | `POST /api/v1/comparisons` | 指标口径、缺失项、结果 |
| 保存触发器 | 编辑条件 | `PUT /api/v1/triggers/{id}` | 校验、启用状态、下次检查 |
| 重新检查 | 主动运行触发器 | `POST /api/v1/triggers/check` | 命中和未命中原因 |
| 删除草稿 | 删除未确认导入 | `DELETE /api/v1/imports/{id}` | 影响说明、确认、结果 |
| 导出数据 | 选择范围 | `POST /api/v1/exports` | 生成状态、下载链接 |
| 测试 AI | 验证配置 | `POST /api/v1/settings/ai/test` | 模型、延迟、脱敏错误 |

实际 API 名称可在实现时细化，但前端、OpenAPI 和测试必须同步变更。

## 4. 导入校对界面

界面同时展示：

- 原图局部；
- OCR 原文；
- 标准化字段；
- 置信度和校验问题；
- 候选基金匹配；
- 重复或冲突来源；
- 修改历史。

低置信度字段默认高亮。涉及基金身份、交易类型、金额/份额和日期的错误必须修复后才能确认。允许部分确认，但必须清楚列出未进入正式数据的行。

## 5. 研究报告界面

报告将“事实”“计算”“规则结论”“AI 解释”分区，避免混为一段文字。每个核心数字应能展开查看：

- 数据来源；
- 截止日期；
- 计算口径；
- 与基准或同类的比较；
- 缺失或陈旧状态。

操作建议区域必须同时显示目标区间、条件、有效期、失效条件、反方观点和风险提示。颜色不能是唯一语义。

## 6. 防止重复提交

- 写操作按钮在请求期间禁用；
- 请求带幂等键或内容哈希；
- 超时后先查询任务状态，再决定是否重试；
- 用户返回上一页后任务继续可见；
- 重复点击不得创建多份候选、报告或交易。

## 7. 错误呈现

错误信息应回答：

1. 哪一步失败；
2. 哪些数据已保存；
3. 用户能否重试；
4. 是否需要更正输入；
5. 去哪里查看详细状态。

不得向前端显示 Python 堆栈、密钥、内部文件路径或 Provider 原始敏感响应。

## 8. 可访问性与桌面体验

- 关键操作可用键盘完成；
- 表单有可见标签和错误关联；
- 焦点状态清楚；
- 对比度符合 WCAG AA；
- 金额和百分比不只依赖红绿；
- 表格支持横向溢出、排序说明和空状态；
- 长任务离开当前页面后仍可在任务中心查看。

## 9. 测试要求

每个可见控件至少具备：

- 组件级状态测试；
- API 契约测试；
- 成功和失败路径；
- Playwright 可执行的用户流程。

CI 增加“交互清单”审查：新增按钮的 PR 必须同时包含事件处理、API/本地动作、可见反馈和测试。静态展示元素不得使用按钮语义。
