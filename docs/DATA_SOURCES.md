# 数据来源规范

## 1. 三条数据通道

### 个人数据

来源：

- 支付宝候选列表截图；
- 持仓和资产构成截图；
- 交易记录和单笔详情截图；
- 用户人工校对或补录。

用途：

- 用户真正关注、持有和交易的基金；
- 当前金额、占比、成本、收益和交易现金流；
- 支付宝实际可购买的份额、限购和平台特有信息。

个人截图不能代替基金公开研究。

### 基金与市场数据

来源：

- 基金管理人和托管人网站；
- 中国证监会基金电子披露网站；
- 上海、深圳证券交易所；
- 中证指数、国证指数等指数编制机构；
- AKShare 等结构化 Provider；
- 未来按权限增加 Tushare。

用途：

- 基金档案、净值、分红、拆分、费率、经理和持仓；
- 业绩基准与指数规则；
- 估值、市场状态和同类比较；
- 可复算的确定性指标。

### 事件证据

来源：

- 官方公告、定期报告和产品资料概要；
- 监管政策、交易所和指数机构公告；
- 可靠财经媒体；
- 普通网页只作为待核验线索。

用途：

- 经理变更、费率变化、限购、暂停申赎、清盘风险；
- 指数规则调整、行业政策和重大事件；
- 正面证据、风险证据、反方观点和未知项。

## 2. 来源等级

| 等级 | 示例 | 使用方式 |
| --- | --- | --- |
| S：法定/官方披露 | 证监会披露平台、基金管理人、交易所、指数机构 | 核心事实首选 |
| A：专业结构化来源 | 经核验的 AKShare/Tushare 接口 | 提高获取效率，保存其实际底层来源 |
| B：可靠媒体 | 权威财经媒体和通讯社 | 事件补充，必须保留发布时间和链接 |
| C：普通网页 | 自媒体、论坛、搜索摘要 | 仅作为线索，不直接进入强结论 |

支付宝截图属于“个人事实来源”，不按以上公开来源等级降级，但必须人工确认并记录截图时间。

## 3. 获取与回退

```text
首选来源返回有效数据
        ↓ 否
读取最近一次有效缓存并标记陈旧
        ↓ 无缓存
尝试备用 Provider
        ↓ 仍失败
标记数据不足，停止依赖该字段的强结论
```

不同来源冲突时：

- 两份原始值均保存；
- 记录差异及来源；
- 不静默选择更有利的值；
- 按字段来源优先级选择工作值；
- 降低数据置信度；
- 超过阈值时阻止操作建议。

## 4. 时间语义

每条数据至少保存：

- `source_name`
- `source_url` 或 Provider 标识
- `value_date` 或报告期
- `published_at`/`announced_at`
- `fetched_at`
- `available_from`
- `quality_status`
- 原始值与标准化值

回测与历史复盘只能在 `available_from` 之后使用数据。季度末持仓不能在实际公告日前进入历史判断。

## 5. 净值与总回报

- 单位净值不等于总回报序列。
- 累计净值、分红、拆分与复权因子必须交叉核验。
- 无法得到可靠总回报时，报告必须说明口径。
- 异常跳变不能静默删除，应检查分红、拆分、数据错误和产品事件。
- A/C 等份额类别必须分别识别，不能仅按基金名称合并。

## 6. 第一阶段 Provider 策略

- AKShare 作为免费便利入口，不被标记为官方来源。
- 对关键基金身份、费率、经理、基准和公告优先核对官方披露。
- Tushare 不作为 v1 启动硬依赖；只有免费来源无法稳定满足字段和频率时再评估。
- 普通 CI 使用固定匿名化响应，不实时抓取外部网站。
- Provider 适配器必须记录上游字段版本和失败原因。

## 7. AI 搜索边界

- DeepSeek 不自行决定搜索哪些网站。
- 应用先按基金、指数、行业、事件和截止日期构造候选文档。
- 规则层过滤未来信息、重复、低可信和无关材料。
- 模型只能看到最终 Evidence Pack。
- 每条模型事件必须引用包内 `evidence_id`。
- 没有证据时输出未知，不用模型常识补齐当前事实。
