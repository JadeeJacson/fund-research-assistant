# 项目当前状态

更新基线：2026-07-29，`main` 提交 `fcdaa578a6ded24de7c34440cc25ae9e19b890d6`。

## 结论

当前仓库是一个约 70 个文件的 `v0.1 Streamlit 原型`，不是空仓库，也不是已经能够可靠输出真实操作建议的成品。它提供了一部分正确的工程边界，但业务数据、判断逻辑、组合能力、前端体验和真实验收仍不完整。

## 当前已有

- Python 3.12 项目与 `pyproject.toml`。
- Streamlit 首页和单基金、组合、AI 证据、数据质量页面。
- AKShare 基金档案与单位净值适配。
- SQLite 数据库与初始表结构。
- 收益、波动、最大回撤、夏普、索提诺和卡玛计算。
- CSV 交易导入、份额聚合和 XIRR 基础函数。
- 文档、证据、AI 调用记录和文件缓存。
- DeepSeek v4 结构化 JSON Provider 与 Mock Provider。
- Pydantic 校验、pytest、Ruff 和 GitHub Actions 配置。
- Windows 安装和启动脚本。

## 当前不足

### 数据

- 基金类型主要依赖名称关键词，缺少可靠分类与份额映射。
- AKShare 净值链路当前主要使用单位净值，分红、拆分和复权总回报未形成完整闭环。
- 基准、同类、基金规模、费率、经理、正式持仓和指数估值尚未形成稳定数据链。
- Provider 失败回退和来源冲突记录仍需完善。

### 判断

- 当前规则主要由年化收益、夏普和最大回撤的硬编码加减分构成。
- “再平衡候选”等状态可能在缺少组合、估值、基准和持仓信息时过早出现。
- 尚未区分 2～3 个月与约 1 年期限。
- 尚未生成仓位区间、买卖触发条件、有效期和失效条件。
- 10% 风险参考线尚未落实为组合压力约束。

### 组合

- 页面主要展示导入后的当前份额。
- XIRR 函数尚未接入完整页面流程。
- 缺少成本、TWR、资产分类、相关性、重叠、集中度、风险贡献和压力测试。

### OCR

- 尚未实现支付宝候选、持仓和交易截图的本地识别、校对、去重与导入批次。
- 尚未区分持仓快照与可用于成本推导的正式交易流水。

### AI

- AI 证据主要依赖手工粘贴。
- 尚未形成官方公告、政策和可靠新闻的自动证据管道。
- 尚未建立正式 Golden Set 和模型升级回归流程。

### 前端与工程

- Streamlit 不适合作为最终复杂校对、批量编辑和未来 C 端产品界面。
- 当前 CI 文件存在，但未发现基线提交对应的工作流运行记录。
- 测试覆盖偏基础，未完成真实 Provider、OCR、API 和浏览器端到端验收。

## v1 迁移原则

- 保留可复用的领域边界、确定性指标、证据引用、安全约束和部分测试。
- 不在旧 Streamlit 页面和旧评分函数上继续无边界扩张。
- 先建立 React/FastAPI 骨架，再按候选研究、OCR、组合、操作建议和 AI 证据逐步迁移。
- 迁移期间旧原型只作为对照和回归参考；当新功能达到验收标准后再删除对应旧入口。
- 每个里程碑完成后更新本文件，禁止 README 超前宣传。
