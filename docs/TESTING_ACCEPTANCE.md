# 测试与验收规范

## 1. 测试层次

| 层次 | 目标 | 主要工具 |
| --- | --- | --- |
| 单元测试 | 金融公式、规则、解析器、领域模型 | pytest、Vitest |
| 契约测试 | Provider、OpenAPI、前后端类型 | pytest、Schema 校验 |
| 集成测试 | 数据库、迁移、任务、缓存、OCR | pytest |
| 组件测试 | 表单、状态、错误和可访问性 | Vitest、Testing Library |
| 端到端 | 用户可见完整流程和按钮 | Playwright |
| 回归集 | OCR、固定市场数据和历史决策 | 脱敏固定样例 |

测试默认离线、确定性、可重复。CI 不依赖实时公开网站或真实 DeepSeek 账户。

## 2. 金融计算

至少测试：

- 单位净值、累计净值和总回报口径；
- 分红、拆分与复权；
- 年化收益、波动、最大回撤和修复期；
- 基准相对收益和跟踪误差；
- XIRR、TWR 及现金流边界；
- 相关性、集中度和压力损失；
- 缺失值、停牌/非交易日和异常值；
- A/C 份额分离。

固定样例必须包含手工可核验的小数据集。浮点误差使用明确容差，不用截图数值作为唯一真值。

## 3. 决策规则

使用表驱动测试覆盖：

- 每个操作状态；
- 每一道数据和产品门控；
- 2～3 个月与约 1 年结论差异；
- 阈值相等、刚超过和刚低于；
- 持续交易日、冷却期和有效期；
- 数据陈旧、来源冲突和未知项；
- 组合超配、主题合计超限和压力损失；
- AI 不可用时结果不改变。

保存历史决策回放样例，规则升级后显式审查差异，不自动更新快照掩盖变化。

## 4. OCR 与导入

OCR 回归至少衡量：

- 字符识别准确率；
- 基金代码和身份准确率；
- 关键字段准确率；
- 多图记录重复率；
- 需人工修订率；
- 未确认数据进入正式库的数量。

安全断言：

- 错误基金身份不可自动确认；
- 金额和份额不可互换；
- 截断名称必须提示；
- 图片重复和业务重复分别检测；
- 确认失败事务回滚；
- 正式数据误写入为零。

## 5. Provider 与证据

- 使用录制或手工构造的匿名响应；
- 校验字段映射、来源、日期、缓存和回退；
- 上游字段缺失或改名时显式失败；
- 官方和聚合来源冲突时保存双方；
- 历史回放不使用当时尚未公开的资料；
- Evidence Pack 去重并过滤低可信线索；
- AI 引用只能指向包内证据。

少量真实 Provider 冒烟测试可手工或定时运行，不作为普通 PR 合并的唯一条件。

## 6. 前端与端到端

关键 Playwright 流程：

1. 启动空数据库；
2. 添加候选并查看身份；
3. 刷新固定 Provider 数据；
4. 生成两个期限的报告；
5. 上传截图并进入校对；
6. 修改低置信度字段并确认；
7. 查看持仓、交易和组合；
8. 保存并检查触发器；
9. 模拟 Provider、OCR、AI 和网络失败；
10. 刷新浏览器确认持久化。

每个可见按钮必须在自动化中至少执行一个成功或失败路径。禁止只断言按钮“存在”。

## 7. 安全与隐私

测试：

- 文件类型、大小和图像解码限制；
- 路径穿越和恶意文件名；
- SQL 注入和输入边界；
- CORS 和本地绑定；
- 日志、错误响应和导出不泄露密钥；
- 原图删除、数据删除和备份恢复；
- 模型请求不包含图片和非必要个人流水；
- 依赖漏洞和许可证检查。

## 8. 合并门槛

每个实现 PR 至少通过：

- 格式化和 lint；
- Python 和 TypeScript 类型检查；
- 单元、契约和相关集成测试；
- 相关 Playwright 流程；
- 数据库迁移升级与回滚测试；
- 文档和 OpenAPI 同步检查；
- 无密钥、无用户原始图片、无生产个人数据。

紧急跳过必须在 PR 中说明原因、影响、临时保护和补测任务。

## 9. 发布验收

本地 v1 发布前必须：

- 在干净 Windows 环境完成安装和启动；
- 从新库导入样例并生成报告；
- 从备份恢复；
- 在无网络、无 AI、单一 Provider 失败时降级；
- 检查全部页面空状态、加载状态和错误状态；
- 完成键盘操作和颜色非唯一语义检查；
- 确认 README 只列出已经验收能力。
